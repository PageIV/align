# align：侧聊入口

把"追问一条回答"和"把回答固定下来"拆成两件事：追问在**侧聊**里做，不污染主线；固定下来的东西由面板逐条勾选、落地。

## 什么时候用

用户指着一条回答——选中一段文字，或者说"关于上一条回答…""这条我不确定""这个前提对吗"。

**不要在主线程里直接展开追问。** 那正是这个插件要避免的：跑题、占上下文，而且追问出来的东西会被压缩吃掉，下一轮它又按旧前提继续。

**没有要追问的、只是想调出表单？** 那是另一个技能（`align-now`）的活：用户直接用 `/` 选它，或者输入框里提 `$align-now`。别把这条路径绕成"先开侧聊"。

## 第一步：把追问交给侧聊

侧聊是 Codex 的原生功能：输入框里发 `/side`（快捷键 `Cmd+Shift+;`）开一个临时侧聊。

1. 把那一段回答**逐字引出来**。用户选了就照抄选中的文字；没选就引原句，不要转述、不要总结。
2. 让用户把这三样东西发进侧聊：
   - 引的那段回答；
   - 他要确认的那一点，一次只问一件事；
   - 纪律：只针对这段回答，单轮，简短。
3. 侧聊会继承这条对话的历史，但那是**只读参考**，不是指令；侧聊里说的话也不会回到主线程。

主线程这边不要再问一遍。

## 第二步：把侧聊的答案整理成候选断言

用户说"这条算数"之后，把答案压成 1–5 条**候选断言**：

- 每条一句话，说的是"我们同意这么说"，不是复述推理过程。
- 每条给一个**建议目的地**。表单不会替用户预选（宿主不给选择型字段默认值），所以你的建议会出现在三个地方：选项的第一项、条目描述里的「建议 X」、以及用户没动过那条时按它处理。这是给人看的建议、不是决定。三个值：
  - `land`（表单上叫 **Align**）——这条以后每轮都得带上：定下来的词义、边界、长期约束。
  - `restate`（表单上叫 **Restate**）——说完一次就失效的：命令式的要求（"这轮先别重构"），或者够不上一条已确认项、但你希望主线知道的一段话。**这类候选尽量照抄原话**，别压缩、别改写成结论——复述的意义就是把那段话原样带回去。
  - `ignore`（表单上叫 **Ignore**）——不留痕。值得让用户看一眼、但不该留下来的，用这个。
- **别拿候选凑数。** 一条一条都要有人读，表单不是清单。单纯是噪音的别放进去；"有点价值但多半不用留"的可以放，然后用 `ignore` 建议他丢掉。
- 每条给一个**标签**（概念对齐 / 错误纠正 / 方向纠偏 / 细节填充）。标签不再决定任何行为，标错只影响账本与热块里的行首前缀；拿不准就不给，服务端按项目里的 `.align/config.toml` 给默认。
- 用 `GLOSSARY.md` 里的词。被禁用的同义词（事实、结论、记忆……）不要出现在断言里。

想避免和已有的条目重复，可以先调 `align_list` 看当前对齐了什么。
用户想自己看、想自己改（"看看对齐了什么""把 C-008 改掉""这条不用了"）时，调 `align_open_ledger` 开账本面板——改标签、取代、退休都在那儿；他也可以直接用 `/` 里的 `align-ledger` 技能自己调出来，不必等你动手。只是想读一眼内容就 `align_list`。

## 第三步：落地

调 `align_land`，把候选断言交给用户。宿主会弹出一张**原生表单**：每条断言一个选择——「Align」写进账本以后每轮带上、「Restate」只把这段带回主线说一次、「Ignore」不留痕。默认停在你的建议上，用户不改就是同意；整张表单都不想决定时他按 skip，那也不是你的失败。提交后插件自己动手，你不用再调 `align_commit`：

- 选「Align」的写进 `ALIGNMENT.md`，从下一次提问起每轮注入；
- 选「Restate」的，**看你在哪儿**：在侧聊里落的进收件箱，用户回主线问下一句时自动带上，一次用完；在主线程里落的，工具会告诉你**在这一轮回复里原样说出来**——用**加粗**或引用块把它标出来，让它在叙述里一眼可见。不要改写、不要总结、不要再解释一遍。

**这张表单在主线程和侧聊里都能弹。** 所以在侧聊里追问完之后，可以让用户直接在那边落完——不必把结论搬回主线程。侧聊里调用它属于改工作区，用户必须已经明确要求；没说就只问不管落地。

- **`root` 必须传当前工作区的绝对路径。** MCP server 的工作目录是插件目录，不是用户的项目；省略会把对齐账本写进插件仓库自己身上。
- `source` 写清这批断言来自哪里（例如 `thread <id> · <日期>`）。它会进账本条目的"来源"字段。

工具结果会分三段告诉你：哪几条落了地、哪几条要你**当场原样说出来**、哪几条进了收件箱。照着做，别自己发挥。

**回报只说结果，一句话说完。** 用户要知道的是"去哪了"，不是内部怎么走的：

- 写进账本的 →「已落地 C-019」，可以补半句"从下一轮起每轮带上"。
- 复述（进收件箱）的 →「已复述，会在你下次提问时到达，只带一次。」到这儿就够。
- 要你当轮说的那一段 → **原样说出来**，用加粗或引用标出来；这一条不能只报"已复述"。
- **不许提**文件名、路径、session id、工具名、字段名（`inline` / `inboxed` 这类），也别把工具结果的结构复述一遍。用户不需要知道这些。

（内联面板那条落地路径**已退役**——见已确认项 C-007：落地统一走 `align_land`。`ui/panel.html` 留在仓库里，是留给工单 08 改造成"查看与编辑账本"的，不再是落地入口。）

## 边界

- **落地不限定在主线程。** 侧聊里也能落（它调得动 `align_land`），只是要用户明确要求。侧聊本身是临时的、那边开的面板也留不住——所以落地的结果必须写进文件或收件箱，写完就和侧聊在不在无关了。
- **追问不要超过一轮。** 一轮问不清，往往说明这条回答本身不够清楚——把它变成一条候选断言比继续追问更诚实。
- **别替用户选目的地。** 你给的是建议，用户不改才是接受。尤其别把命令式的内容建议成 `land`——它之后每轮都会出现，等于每轮重复一道命令。
- **旧的那条不对了，就取代它，别再加一条。** 用户说"那条过时了/不对了，应该是 X"时，把 X 作为候选、在它上面填 `supersedes: "C-0NN"`。用户确认后旧条目会被标成 `superseded`，留在账本的历史里，但不再每轮注入。不填 `supersedes` 就是纯新增——两条会一起生效，那通常不是你想要的。
- **"这条不用了"是退休，不是取代。** 没有别的话要说、只是这条不再成立时，走 `align_open_ledger` 面板上的「退休」（或调 `align_edit` 带 `retire`）。取代是"改成这样说"，退休是"这话不用再管了"——**删除不存在**，条目永远留在账本的历史里。
- **不要在代码或文案里写死那几类标签。** 增删类型只改 `.align/config.toml`，名字由服务端现读配置给出。

## 宿主没有侧聊时

退一步：把这一轮追问直接放在主线程里，但守住同一条纪律——只针对那一段回答、单轮、简短。隔离没有了，所以这只是退路，不是等价替代。

**不要用派生子代理来假装隔离。** 2026-10-05 实测五次：`fork_turns: "none"` 的子代理有四次根本没收到任务正文；唯一收到的那次，它也照样看得见项目层的 `AGENTS.md`、照样读文件和跑命令。而且用户没法直接在里面追问，只能由主线程转述——转述本身就把内容带回主线程了。
