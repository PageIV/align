# align：侧聊入口

把"追问一条回答"和"把回答固定下来"拆成两件事：追问在**侧聊**里做，不污染主线；固定下来的东西由面板逐条勾选、落地。

## 什么时候用

用户指着一条回答——选中一段文字，或者说"关于上一条回答…""这条我不确定""这个前提对吗"。

**不要在主线程里直接展开追问。** 那正是这个插件要避免的：跑题、占上下文，而且追问出来的东西会被压缩吃掉，下一轮它又按旧前提继续。

## 第一步：把追问交给侧聊

侧聊是 Codex 的原生功能：输入框里发 `/side`（快捷键 `Cmd+Shift+;`）开一个临时侧聊。

1. 把那一段回答**逐字引出来**。用户选了就照抄选中的文字；没选就引原句，不要转述、不要总结。
2. 让用户把这三样东西发进侧聊：
   - 引的那段回答；
   - 他要确认的那一点，一次只问一件事；
   - 纪律：只用这段回答，单轮，简短，不调工具。
3. 侧聊会继承这条对话的历史，但那是**只读参考**，不是指令；侧聊里说的话也不会回到主线程。

主线程这边不要再问一遍。

## 第二步：把侧聊的答案整理成候选断言

用户说"这条算数"之后，回到**主线程**再动手。侧聊是临时的，宿主也禁止它改工作区——落地不要在那边做。

把答案压成 1–5 条**候选断言**：

- 每条一句话，说的是"我们同意这么说"，不是复述推理过程。
- 每条给一个建议类型。类型是开放集合（`align_review` 会把当前可用的类型表给你），拿不准就不给，服务端会按项目里的 `.align/config.toml` 给默认值。
- 用 `GLOSSARY.md` 里的词。被禁用的同义词（事实、结论、记忆……）不要出现在断言里。

想避免和已有的条目重复，可以先调 `align_list` 看当前对齐了什么。

## 第三步：开面板

调 `align_review`，把候选断言交给用户勾选。面板在**主线程**里内联渲染，它才是界面——你的回复一句话就够。

- **`root` 必须传当前工作区的绝对路径。** MCP server 的工作目录是插件目录，不是用户的项目；省略会把对齐账本写进插件仓库自己身上。
- `source` 写清这批断言来自哪里（例如 `thread <id> · <日期>`）。它会进账本条目的"来源"字段。

用户在面板里勾选、改类型、点落地。落地写 `ALIGNMENT.md` 并更新 `AGENTS.md` 里的受管区块；`restate` 为真的类型，面板还会替你发一条可见卡片，触发复述。

## 边界

- **落地一律回主线程。** 侧聊只用来追问：它是临时的，面板开在那边也落不了。
- **追问不要超过一轮。** 一轮问不清，往往说明这条回答本身不够清楚——把它变成一条候选断言比继续追问更诚实。
- **不要在代码或文案里写死那几类类型。** 增删类型只改 `.align/config.toml`，类型的名字与行为都由服务端现读配置给出。

## 宿主没有侧聊时

退一步：派一个只带那段回答加必要上下文的隔离子代理（`fork_turns: "none"`，不带主线历史），同样守上面的纪律；它的答复就当侧聊的答复用。这条路的缺点写在明面上：用户没法直接在里面追问。
