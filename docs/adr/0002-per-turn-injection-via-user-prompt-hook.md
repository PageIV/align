# ADR-0002：每轮注入走 `UserPromptSubmit` 钩子，不走 `AGENTS.md` 受管区块

- 状态：已接受
- 日期：2026-10-05

## 背景

需求是"每一轮提问，主 Agent 都拿到当前生效的已确认项"。最早的载体是在 `AGENTS.md` 里维护一个受管区块，理由是 App 会自动读它，插件什么都不用做。

工单 11 的真机实测推翻了这条前提：`AGENTS.md` 只在 app 重启或线程重载时读一次，**不是每轮**。在一条已经跑了几轮的线程里落一条新条目，同一线程的主 Agent 说不出它——文件跨了回合边界变了，注入进去的那份没变。

## 决定

每轮注入交给插件的 `UserPromptSubmit` 钩子：它在你发出提问的那一刻从 `ALIGNMENT.md` 现渲染热块，以 `hookSpecificOutput.additionalContext` 输出。`AGENTS.md` 的受管区块退役。

选钩子而不是受管区块，有三条实测依据：

- **时机**：钩子在提问那一刻运行，读到的是当时最新的账本——侧聊刚落的、面板刚改的，只要在下一次提问前落盘，就一定会被带上。
- **归属**：钩子是插件自身的一部分，`hooks/hooks.json` 在插件根下自动发现，`plugin.json` 不用加字段。
- **形态**：`additionalContext` 进模型上下文，而且是**贴在用户那条消息后面**到达，拿的是用户级位置。所以热块的效力规则必须写成三级——与更早的对话冲突时以此为准，**但用户当前这条消息优先**。

## 考虑过的替代方案

- **`AGENTS.md` 受管区块**：否决。只在 app 重启 / 线程重载时读一次，中途是陈的。
- **两者并存**：否决。同一份前提会在一轮里出现两次，而且两个通道给出的是不同版本（受管区块那份是旧的）。
- **每轮由模型显式调 `align_list`**：否决。那要靠模型自觉，等于退回"不保证"。

## 后果

- **钩子要过信任审核，且重装后要重新过一遍。** 未信任的钩子宿主**静默不跑**：没有报错、也没有跳过说明。这是这套方案最贵的运维代价，已写进 README 与交接。
- 账本仍是唯一权威来源（人可读、可 diff、可进 PR）；热块不是一个文件，是钩子在提问那一刻渲染出来的东西。
- **没有用户提问的轮次（子代理、自动化）拿不到账本。** 这是退役受管区块的真实代价；眼下没有证据说子代理需要它，需要时再挂 `SubagentStart`。
- **线程作用域重新变得可实现。** 钩子输入里带 `session_id`（= 线程 ID），按线程渲染技术上可行，只是还没有要解决的问题，暂缓。
