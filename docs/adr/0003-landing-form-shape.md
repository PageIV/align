# ADR-0003：落地表单的形态——一问一页，一条候选一个字段

- 状态：已接受
- 日期：2026-10-07

## 背景

落地 UI 是宿主原生的 elicitation 表单（C-005、C-012）。它不是一张能随便排版的画布：形状由宿主定，插件只能填 `message`、题目文字、描述行、选项文字这四处。试了两轮才发现边界在哪，两次都被真机否掉。

宿主的三条硬约束（读 `app.asar` 得来）：

1. **一问一页的分步向导。** i18n 里有 `mcpFormElicitation.next` / `.continue` / `.progress`（"{current} of {total}"）/ `.skipQuestion`（"暂时跳过"），页面按**字段**翻。
2. **选择型字段不预选。** 初始化表单状态时 string + enum/oneOf/anyOf 一律跳过；`default` 只对文本、布尔、数字生效。
3. **选项只有 `{const, title}` 两个位置**，放不下 hover 说明。

## 决定

**一条候选 = 一个字段。** 那句话就是那一页的**问题文字**，下面三个选项（Align / Restate / Ignore，建议那一项排第一）。

- 每个选项的文字里带一句解释（`enumNames`）：`Restate · 只带回主线说一次`。顶部不再摆图例。
- 顶部 `message` 只留**一行标题**（一条候选「这条去哪？」、多条「逐条选去哪」）——它不是说明，是那张卡的头部。
- 建议落在三处：枚举顺序、描述行里的「建议 X」、以及回传缺这个 key 时按建议处理。

## 考虑过的替代方案

- **一条候选两个字段（可编辑的内容框 + 去哪）。** 0.2.15 做了，真机当场否掉：向导按字段翻页，两个字段就是两页，用户要先翻过去才能选。
- **顶部写一段说明 / 图例**（`Align = … / Restate = … / Ignore = …`）。到 0.2.14 为止是这样，主次不清——说明淹掉了条目本身。
- **顶部完全空着。** 0.2.16 试了，问题文字直接贴到表单框顶（"文字太靠上"）。
- **在面板里落地**（`align_review`）。已退役，落地只有表单一条路（C-007）。

## 后果

- **表单里改不了措辞。** 要改就落地之后到账本面板点「改」（走取代）。这是"一问一页"的直接代价，不是漏做。
- **选项文字偏长**，因为它是解释的唯一去处。以后想加说明，先问自己能不能塞进这一行。
- 任何"给表单加个输入框 / 加个说明"的想法，都得先回答这条约束：**多一个字段就是多一页**。
- 形状全部收在 `logic/landing-form.mjs`，有测试盯着（字段数、`enum` 与 `enumNames` 对齐、顶部那一行、回传怎么读）。
