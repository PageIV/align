# 18 — 落地表单：一问一页，句子在问题上

Status: 待真机复验
Blocked by: 14
Type: task

## 现象（2026-10-07 真机）

用户在侧聊里看到表单后报三条：

1. **主次不清**——顶部一大段图例（`Align = … / Restate = … / Ignore = …`），条目本身反而淹没在里面。
2. **名词解释不该常驻**——最好是鼠标指到标签上再显示。
3. **要复述的内容看不见**——那段话只作为字段标题出现，用户不确定被带回去的是不是这句。

## 宿主能做什么（读 app.asar）

- 选项被收敛成 `{const, title}` 两个键（`gXn`）——**没有位置放 hover 说明**。第 2 条只能落成"解释并进选项文字"（`enumNames` 支持）。
- 文本字段吃 `default`（`vXn` 只跳选择型字段）——第 3 条看上去能做。
- **但表单是「一问一页」的分步向导**：i18n 里有 `mcpFormElicitation.next` / `.continue` / `.progress` / `.skipQuestion`（"暂时跳过"），`customChoice` 是"其他"。

## 走过的弯路（0.2.15，已被真机否掉）

按第 3 条做成"一条候选两个字段"：上面一个可编辑的内容框（预填 statement），下面一个去哪的选择。真机上用户看到的是**每条候选翻两页**——先看到选项，还得翻过去才能看/改文本。用户原话："这两页做到一起不就可以了吗"。

做不到。"一个字段里同时放可编辑文本和选项"没有位置——向导按字段翻页，两个字段就是两页。

## 最终形状（0.2.16）

- **一条候选 = 一个字段**：那句话就是那一页的**问题文字**（和选项同页），描述行写「第 N 条 · 建议 X · 标签 Y」，下面三个选项。
- 顶部 **`message` 给空串**（宿主把它钉在每一页上，且它要说的事在别处都有）。
- 选项文字继续带解释：「Restate · 只带回主线说一次」。
- 想改措辞就落地之后到账本面板点「改」（走取代）——那里才是改文字的地方。

## 验收标准

1. 真机：一条候选只翻一页，那句话和三个选项在同一页上。
2. 真机：表单顶部没有那段说明文字，也没有图例。
3. 真机：三个选项各自的文字里带解释。
4. 真机：`message` 给空串后宿主照常渲染（不报错、不留一块空白）。
5. `npm test`：一条候选一个字段、问题文字就是那句话、顶部 message 为空、`enum`/`enumNames` 逐项对齐、建议位置、整句标签认得回来。
