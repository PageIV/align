# 09 — 注入后端可替换 + 压缩兜底

Status: wontfix
Blocked by: 05
Type: task

## 目标

线程层的持久性建立在"对话历史"上，而压缩会不会吃掉它**没有实测**。把这一层抽象出来，等哪天压测出结果，换掉它不用动 `logic/`。

## 交付

- 一个注入后端接口（把"往对话里放东西"抽象成一个方法），当前实现是 MCP Apps 的两个通道
- 一个可配置的重要程度阈值：达到阈值的条目，落地时提示直接走项目层
- 文档写明：压缩对线程层的影响未知，以及两种结果下各自的兜底策略

## 验收标准

1. 替换注入后端不需要修改 `logic/` 下任何文件。
2. `README` 或规格里有一段"压缩未知 + 兜底"的说明，与 `.scratch/align/spec.md` 的"仍未验证"一致。
3. 达到阈值的条目在面板上有明确提示。

## 上下文指针

- `.scratch/align/spec.md` 的"仍未验证"
- `docs/adr/0001-align-codex-first-host-agnostic-core.md`

## 结论（2026-10-05）

不做了。这张票要解的悬念是"压缩会不会吃掉线程层的那点上下文"，而线程层已经作废（工单 05）——每轮注入改由 `UserPromptSubmit` 钩子从 `ALIGNMENT.md` 现渲染，不依赖对话历史，压缩影响不到它。可替换的注入后端也就没有要替换的东西了。
