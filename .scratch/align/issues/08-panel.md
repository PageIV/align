# 08 — 面板成形

Status: 待真机复验
Blocked by: 03, 04, 05
Type: task

## 目标

把 02 那个"一个输入框"的占位面板做成真正能用的界面。面板是"给我一个选择"这个产品核心的物理形态，做差了整个插件就没了意义。

**2026-10-05 改向**：落地 UI 已经换成宿主原生表单（工单 14），面板**不再是落地入口**（已确认项 C-007）。这张票剩下的价值是"**查看与编辑账本**"——列出生效项、改一条措辞、退休/删除、看 supersede 链。下面"交付"里与落地选择有关的部分按这个新定位重读。

**2026-10-05 决定**：`align_review` 已从工具面摘掉（`ui/panel.html` 留在仓库里）。挂回去的时候按"查看与编辑账本"做，不要恢复成落地面板——落地只有 `align_land` 一条路。

**2026-10-05 实测：渲染面板会留下宿主残留，而且是两种，别搞混。**

1. **单页签面板的空窗口壳。** 当初 `align_review` 渲染出的面板被宿主开成了一个单页签面板窗口（`appShell.singleTab.*`，`appShell.singleTab.close` = "关闭面板"）。工具摘掉之后宿主拿不到内容渲染，窗口壳留着，里面只剩宿主自带的"变更"页签。
2. **对话侧边面板本身卡住。** 那张卡里的条目属于 `codex.localConversation.*` 这一族：`diffTab`=变更、`sources.title`=来源（`showAll`=查看全部）、`outputs.title.v2`=输出内容、`artifacts.create`=创建文件或站点。也就是说它是**宿主的右侧面板**，分区是"变更 / 来源 / 输出内容"。症状：重启不清除（状态持久化），切到别的项目只换内容、容器还在，UI 上找不到关闭入口。

   它对应的宿主命令是 `toggleSidePanel`（标题文案 `codex.command.toggleReviewPanel` = 显示/隐藏"变更"面板，`commandMenuGroupKey: panels`），**默认快捷键 `CmdOrCtrl+Alt+B`**；另有一个 `toggleMaximizeSidePanel`。用户侧先试这个快捷键，再试命令菜单里 `panels` 那一组。

两者的处置都在宿主那边（Esc / 切换线程 / 重启 app），插件够不着。留在票里是为了**做账本查看器时把这两种残留当成已知风险**：面板的生死不该连累宿主 UI 的其它部分。

这条要带进实现：

1. 面板退役/不可用时，用户必须能把它关掉——别依赖宿主自动收。
2. 挂回去时想清楚"渲染不出来"的兜底状态。`ui/panel.html` 已经有一版"这里没有 MCP 宿主"的文案，可以按同样的思路写一个"这次开不出来"的状态。
3. 顺带记住这个形态：单页签时面板自带表头（图标 + 标题 + 右上角菜单），多页签时才把"在应用里打开"插进页签条（`RightPanelTabListAfter`）。做账本查看器时按多页签那支设计，会更容易和宿主自带的面板共存。

## 交付

- `align_open_ledger` 打开面板；内联渲染在对话里（也能展开成侧边面板）
- **生效中**：每条列 id · 标签 · 日期 · 断言
- **改动三种**：改标签（原地改）、改措辞（走取代，旧的留痕）、退休（不再生效，没有后继者）
- **已失效**：只读，显示取代链（"已由 C-009 取代"）或"已退休"
- 在 ~371px 宽度下可用；纯内联 CSS/JS，不引任何外部资源
- 没有宿主时给一个可读的失败状态，而不是一排死按钮

## 验收标准

1. 面板在侧边栏 371px 宽下无横向滚动、无截断。
2. 打开后看见的生效 / 已失效条数与 `ALIGNMENT.md` 一致。
3. 改标签：编号不变、条数不变，热块下一轮里那条的前缀变了。
4. 改措辞：长出新编号，旧的进"已失效"并显示取代链；热块下一轮只带新的。
5. 退休：条目仍在文件里（状态 `retired`），热块不再带它。
6. 所有资源内联；断网也能用。
7. 面板上的文案与 `GLOSSARY.md` 的说法一致，不出现"记忆""事实""上下文注入"这些被禁用的词。

## Comments

- 2026-10-06 · 实现完成（0.2.8）。三处设计取舍：
  - **"改措辞"落成取代，不是原地改。** 面板上看起来是编辑一个文本框，底下是新条目 + 旧条目标 `superseded by`。理由：账本的第一原则是"旧的不能删"，改一句话就是"我们曾以为是 X、后来改成 Y"的标准场景。改标签相反，原地改——标签只是给人看的前缀。
  - **加 `retired`，并征得用户同意**（用户 2026-10-06 明确说"你可以加一个 retired"）。取代是"改成这样说"，退休是"这话不用再管了"——没有后者，像 C-003 那种条目就只能靠取代硬凑一个后继者。**删除仍然不存在**。
  - **面板不再碰落地**（C-007）。它只读账本、只改已有条目；新条目一律走 `align_land` 的原生表单。工具面因此多两个：`align_open_ledger`（开面板）与 `align_edit`（改标签 / 取代 / 退休）。
- 2026-10-06 · 关于那个"关不掉的侧边面板"：用户看过之后确认**那是 Codex 自带的**面板，不是我们渲染出来的残留，所以不必绕开 MCP App 这条路。票里 2026-10-05 那条残留记录保留，但按"宿主自己的东西"处理。
- 2026-10-06 · 离线验证：假宿主驱动真实 server 跑通五个动作——打开账本、改标签（编号不变）、改措辞（长 C-003、C-001 变 `superseded by C-003`）、退休（`retired`）、对已失效条目退休（正确报错）。面板脚本单独做了语法检查。**渲染、371px 布局、按钮点到即生效这三件事要真机看。**
- 2026-10-07 · **真机第一轮：功能全对，两处要改。** 用户在面板上真做了一遍：C-006 改标签（原地、编号不变）、C-003 退休（掉出热块，条目还在文件里）——两个都生效，注入里 items 从 11 变 10。发现的毛病：
  - **类型下拉在收起状态是一片空白**，鼠标挪上去才显示。原因是我们把 `background` 设成了 `transparent` 而 iframe 的底色不由我们定，原生 `<select>` 的收起态绘制跟它撞了。**改成不用 `<select>`**：四个标签做成一排小按钮（chip），当前那个高亮。按钮没有这个毛病，也更窄。
  - **面板开在主线里**。现在握手之后立刻发 `ui/request-display-mode { mode: "fullscreen" }`——宿主支持 `inline` / `fullscreen` / `pip` 三种（在 app 里读到的枚举），`fullscreen` 就是侧边那个全屏面。宿主不给展开时顶部会写明"用右上角的展开按钮"，不假装。
- 2026-10-07 · 用户还提了一条：**面板要有自己的手动入口**，跟 `align-now` 一个路子。加了 `skills/align-ledger`（`/` →「技能」→ align-ledger）：立刻调 `align_open_ledger`，不先念一遍内容、也不弹表单。
- 2026-10-07 · 待办（用户明说"现在先不急"）：**整体美化**。这轮只做了不破版的最小调整。
- 2026-10-07 · **0.2.12：美化做掉，外加一个 bug。** 用户说面板已经没问题了，点名走美化。
  - **样式重做**：半透明灰的变量表（`--line` / `--fill` / `--accent` / `--danger`），因为面板底色由宿主定，写死色值会在另一个主题下崩；唯一两处彩色是强调色与"退休"的红。
  - 条目卡：编号与类型各成一个 pill，日期退到后面；编辑中的卡加强调色描边与光环；已失效用虚线边框 + 压暗，跟生效区一眼分开。
  - 按钮：改成 `button.primary`（取代）与 `button.danger`（退休）两种，退休是红的——它不可逆，值得一个警告性的样子。加 `:focus-visible` 键盘焦点环。
  - 顶部：加了内联 SVG 标记、一个"刷新"按钮，计数从一行状态文字搬进两个分区标题（`生效中 9` / `已失效 16`）。
  - **顺手修掉一个 bug**：原来 `openInSidePanel()` 写下"宿主没有展开面板…"之后立刻 `render()`，而 `render()` 会把这个提示覆写成计数——也就是说 README 里承诺的那句提示**从来没显示过**。现在提示与计数分了两个元素，提示清掉后不再被覆盖。
  - **文案对账**：编辑态的按钮原来写"保存（取代）"——`保存` 是词表里的禁用词，改成"取代"。全面板文案重新过了一遍，没有禁用词。
  - 纯内联 CSS/JS，无外部资源；脚本块做了语法检查，`npm test` 73/73。
